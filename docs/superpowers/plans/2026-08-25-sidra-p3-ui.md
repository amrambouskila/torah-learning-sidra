# P3 — The UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this
> plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Six screens over the nine P2 endpoints, with the two-marker rail as the signature.

**Architecture:** React 18 + TypeScript strict, Vite, Redux Toolkit, React Router. One concept per
file. The rail is a windowed list fetched in ordinal spans, because the Mishneh Torah chavrusa
tracks are 15,143 halachos and no browser renders that unvirtualized.

**Tech Stack:** React 18 · TypeScript strict · Vite · pnpm · Redux Toolkit · React Router ·
Vitest + React Testing Library · nginx (production) · Docker.

**Spec:** `docs/superpowers/specs/2026-08-24-torah-sidra-design.md` §9 (screens), §10 (design
language), §11 (infrastructure).

## Global Constraints

- Frontend host port **5285**. Backend **8285**. Never bind host 5432.
- TypeScript **strict**, no `any`, no `@ts-ignore`. `const` by default, never `var`.
  Prefer `interface` for object shapes.
- **One concept per file.** `PascalCase.tsx` components, `useCamelCase.ts` hooks,
  `camelCaseSlice.ts` slices, `PascalCase.ts` types.
- **Vitest + React Testing Library.** Never Jest. `tests/setup.ts` must call `cleanup()` in
  `afterEach` — Vitest does not auto-cleanup and component tests leak DOM state without it.
- **Coverage 100%**, gated by a dedicated command, never by default config.
- **Hebrew is never hand-encoded.** It arrives from the API as UTF-8. No numeric character
  references anywhere. Every Hebrew string renders inside `dir="rtl"` with `unicode-bidi: isolate`.
- **Typefaces** (Google Fonts): **David Libre** 400/500/700 (Hebrew), **Spectral** (Latin display
  and body), **IBM Plex Mono** with `tabular-nums` (every countable value). David Libre runs
  optically small — Hebrew gets its own size step ~10% above the Latin, and row headlines use
  weight **500**, not 400.
- **Dark, hairline construction.** Structure in `rgba(255,255,255,.07)` borders and 1px rules.
  Real shadows only on overlays.
- `prefers-reduced-motion` collapses all animation.
- No `dangerouslySetInnerHTML`. nginx ships a restrictive CSP.

# Task 1: Rail paging endpoint

**Delivers:** the backend addendum the rail needs.

**Files:** `backend/src/sidra/api/routers/tracks.py` · `backend/tests/api/test_tracks.py`

Today `GET /api/tracks/{id}` returns a window of radius ≤ 100 around the markers. The Track screen
needs to scroll the whole spine, so it fetches spans as they come into view.

**Interfaces produced:**
`GET /api/tracks/{id}/rail?from=<int>&to=<int>` → `list[RailUnit]`, capped at 500 units per call,
422 past the end.

- [ ] **Step 1:** TDD the span endpoint — a span returns exactly its ordinals; a span past the end
      clamps rather than erroring; an inverted span is 422; over the cap is 422.
- [ ] **Step 2:** Both markers are flagged inside a span that contains them, and absent otherwise.

# Task 5: The Rail — the signature component

**Delivers:** two markers on one spine, virtualized.

**Files:** `frontend/src/components/{Rail.tsx,RailNode.tsx,RailSpine.tsx}` ·
`frontend/src/hooks/useRailWindow.ts` · `frontend/src/styles/rail.css` + tests

The gap between the lit segment and the ghost marker **is** the debt, rendered literally.

- [ ] **Step 1:** `RailNode` — a circle on the spine; `data-state` of `done | actual | between |
      scheduled | ahead`. The node is the control, as TV's `WatchNode` is.
- [ ] **Step 2:** `RailSpine` — the 1px line, thickened and accent-dimmed up to the actual marker,
      hairline beyond it.
- [ ] **Step 3:** `useRailWindow` — given `total` and the two markers, compute the visible ordinal
      span and fetch it; cache spans already fetched.
- [ ] **Step 4:** `Rail` — virtualized list; only the visible span is in the DOM.
- [ ] **Step 5:** Tests — 150 nodes lit to 28b with the ghost at 38b; a 5,349-unit track keeps the
      DOM node count bounded; `prefers-reduced-motion` disables the transitions.
